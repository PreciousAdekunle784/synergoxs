THE FIX YOU ASKED FOR

  The opt-in was landing people on the "book your call" page (/apply)
  instead of the payment page. Cause: the Paystack button on the offer
  page fell back to /apply whenever Paystack wasn't configured yet.

  Fixed. Now:
    - Every conversion CTA -> opt-in -> /offer (the payment page). Never /apply.
    - The Paystack button on /offer opens inline checkout ON the page.
      If Paystack isn't set up yet, it shows a short "checkout is being
      set up" note and STAYS on /offer — it never bounces to /apply.
    - ONLY the /learn page routes to "book a call" (/apply), exactly as
      you wanted, plus one small "not ready? book a call" link at the
      very bottom of /offer.

PAYSTACK — NOW VERIFIED & CORRECT
  - Integration matches Paystack's official inline v1 API (checked
    against their docs): PaystackPop.setup({ key, email, amount,
    currency, ref, metadata.custom_fields, callback, onClose }) +
    handler.openIframe().
  - metadata now uses custom_fields so the offer/source show on your
    Paystack dashboard.
  - amount is forced to an integer (kobo).
  - Payment is VERIFIED SERVER-SIDE: on success the button calls your
    verify-payment Edge Function, which re-checks the transaction with
    your secret key before marking the buyer paid and sending them to
    /guide. A "paid" state can't be faked from the browser.
  - Set an EXPECTED_AMOUNT_KOBO secret (= 19999900) so an underpayment
    is rejected.
