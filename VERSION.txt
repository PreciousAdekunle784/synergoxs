SYNERGOX SITE — BUILD 13
========================

FOUR THINGS IN THIS BUILD

1) LEADS NOT RECORDING — now diagnosable + likely fixed
   The old subscribe function hid database errors (logged them but
   still returned success), so nothing saved and you saw no error.
   Now it RETURNS the real reason (500 with a clear message + hint),
   visible in your browser Network tab and the function logs.
   >>> The actual fix is almost always: RUN THE MIGRATION (the `leads`
       table didn't exist) or DEPLOY THE FUNCTION.  Step-by-step with
       a curl test is in  FIX_LEADS.txt — read it first.
   Also added a guard: if the function is missing its service-role key
   it now says so instead of silently failing.

2) PAYSTACK NOW IN-PAGE (v2)
   Upgraded from Paystack Inline v1 to v2 (js.paystack.co/v2/inline.js,
   newTransaction). The whole payment flow starts AND finishes on the
   offer page — no redirect away. (Paystack always shows its card form
   in a secure iframe for PCI reasons; v2 is the closest to "in-page" —
   the buyer never leaves synergox.co/offer.)

3) POST-PAYMENT PAGE IS NO LONGER CALL-RELATED
   After paying, buyers now land on  /thank-you  (a proper purchase
   confirmation: receipt on the way, onboarding form, "we map your
   system, we build, you approve"). It says NOTHING about booking a
   call — they bought a build, not a call. (Old flow wrongly sent them
   to /guide, the post-booking call page.)

4) OFFER PAGE — WHAT YOU GET + COMPARISON TABLE
   - Kept the 6 concrete deliverables ("what we actually build").
   - Added a COMPARISON TABLE: Do it yourself vs A freelancer vs A
     typical agency vs Synergox — across whole-system build, funnels,
     paid ads (judged on cost per customer), asset ownership, time cost,
     retainer, and the scope guarantee.
   - Reframed copy around the agency (funnels, ads, growth), not the book.
