SYNERGOX — GOING LIVE
=====================

About twenty minutes, once. Nothing here needs a code change.

Until each step is done the site still works and says so honestly: without
payments switched on, checkout tells buyers online payment isn't available
and takes nothing; without email, the Blueprint is still handed over as a
direct download.


1. DATABASE  (Supabase → SQL Editor)
------------------------------------
  If you haven't already, run   supabase/migrations/0002_admin_dashboard.sql
  Then run                      supabase/migrations/0003_sales_funnel.sql

  Both are safe to run more than once and never delete existing leads.
  0003 adds packages, the Growth Suite bundle, the exit offer, orders, email
  subscribers and funnel events, and seeds the three starting packages:

      Website Foundation        ₦100,000
      Customer Acquisition      ₦120,000
      Conversion Optimization    ₦80,000
      Complete Growth Suite     ₦200,000   (₦300,000 bought separately)

  These are starting figures. Change them in the dashboard (step 6).


2. KEYS  (Vercel → Project → Settings → Environment Variables)
--------------------------------------------------------------
  See .env.example for every variable and where to find it.

    NEXT_PUBLIC_SITE_URL        https://synergox.co
    SUPABASE_SERVICE_ROLE_KEY   Supabase → Project Settings → API (service_role)
    PAYSTACK_SECRET_KEY         Paystack → Settings → API Keys (start with sk_test_)
    RESEND_API_KEY              resend.com → API Keys
    EMAIL_FROM                  SYNERGOX <hello@synergox.co>  (verified domain)
    CRON_SECRET                 any long random string

  Then REDEPLOY. Server keys are read at runtime, but the deploy is what
  picks up the new values and the daily email schedule in vercel.json.

  Secrets go in Vercel only. Never in the code, never in a NEXT_PUBLIC_ name.


3. PAYSTACK WEBHOOK
-------------------
  Paystack → Settings → API Keys & Webhooks → Webhook URL:

      https://synergox.co/api/paystack/webhook

  This confirms payments even when a buyer closes the tab before coming back
  to the site. (Test and live mode each have their own webhook field.)


4. EMAIL DOMAIN  (Resend)
-------------------------
  Add synergox.co in Resend → Domains and create the DNS records it shows.
  Until the domain is verified Resend refuses to send from it, and the
  dashboard's Emails screen will show each failure and its reason.


5. REHEARSE WITH A TEST KEY
---------------------------
  With PAYSTACK_SECRET_KEY = sk_test_…:
    a. Open the site in a private window. Request the Blueprint with your own
       email. You should land on the sales page, and email 1 should arrive
       with a working download link.
    b. Buy the cheapest package with Paystack's test card
       (4084 0840 8408 4081, any future date, CVV 408, PIN 0000, OTP 123456).
       You should see the confirmation page and get a receipt; the business
       inbox gets a "New order" notice.
    c. Fill in the project brief. The business inbox gets "Brief received".
    d. Dashboard → Orders shows the order as Paid, with the brief.
    e. Dashboard → Emails → "Send this one to me" on each email to read them
       in a real inbox.
  Then swap in the sk_live_ key, set the live webhook URL, and redeploy.


6. THE DASHBOARD  (yoursite.com/admin)
--------------------------------------
  Sign-in setup is in ADMIN_SETUP.txt. After that:

    Packages            names, prices, deliverables, scope, on/off, order
    Growth Suite        which packages are in it and its price; the combined
                        value and saving are calculated for you, and a price
                        that isn't a real saving can't be saved
    Exit-intent offer   wording, an optional exit-only price, when it shows
                        on desktop and phones, how long it stays hidden
    Emails              the seven emails, previews, sends, failures
    Website content     headlines on both pages, case study, testimonials

  Settings → Data sources shows which of the steps above are done.


HOW THE MONEY IS PROTECTED
--------------------------
  • The browser never says what to charge. It names a package; the database
    works out the price; the server tells Paystack.
  • An order becomes Paid only when Paystack itself confirms a successful
    charge for at least the full amount in the right currency, either when
    the buyer returns or through the signed webhook. Arriving on the success
    page proves nothing on its own.
  • Callback and webhook can both arrive: the receipt is still sent once.
