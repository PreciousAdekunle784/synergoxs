FIX: "supabaseUrl is required" / LEADS NOT RECORDING
====================================================

You saw this in the subscribe function logs:
    Error: supabaseUrl is required
    ... then "shutdown"

CAUSE (this was a real bug, now fixed):
The function needs your project URL + service-role key. Supabase
RESERVES the "SUPABASE_" prefix for its own secrets — you can't reliably
set SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY yourself, and in your
deployment they weren't reaching the function, so the client got an
empty URL and crashed before saving anything.

THE FIX: the function now reads NON-reserved secret names:
    PROJECT_URL        = your project URL
    SERVICE_ROLE_KEY   = your service_role key

DO THIS (3 steps)
-----------------

1) Set the two secrets (names WITHOUT the SUPABASE_ prefix):

   Using the CLI:
     supabase secrets set PROJECT_URL=https://YOURPROJECT.supabase.co
     supabase secrets set SERVICE_ROLE_KEY=eyJ....(your service_role key)

   Or in the dashboard:
     Project Settings → Edge Functions → Secrets → Add new secret
        PROJECT_URL       = https://YOURPROJECT.supabase.co
        SERVICE_ROLE_KEY  = (paste the service_role key)

   Where to find these:
     Project Settings → API
       - Project URL          → PROJECT_URL
       - service_role key      → SERVICE_ROLE_KEY   (NOT the anon key)
       (the service_role key is secret — it only ever lives in Supabase,
        never in the website code.)

2) Make sure the `leads` table exists:
     SQL Editor → paste & run supabase/migrations/0001_leads.sql

3) Redeploy the functions so they pick up the new code + secrets:
     supabase functions deploy subscribe
     supabase functions deploy verify-payment


CONFIRM IT WORKS
----------------
Quick direct test (replace URL + ANON key — anon, not service_role):

  curl -i -X POST \
    "https://YOURPROJECT.supabase.co/functions/v1/subscribe" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer YOUR_ANON_KEY" \
    -H "apikey: YOUR_ANON_KEY" \
    -d '{"name":"Test","email":"test@example.com"}'

  200 {"ok":true}                → saved. Check Table Editor → leads.
  500 {"stage":"config"...}      → PROJECT_URL/SERVICE_ROLE_KEY not set (step 1)
  500 {"stage":"database"...}    → table missing, run the migration (step 2)

Then do a real opt-in on the site and confirm the row appears in
Table Editor → leads.
